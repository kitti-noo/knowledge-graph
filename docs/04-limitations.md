# 4. ข้อจำกัดและสิ่งที่ควรทำต่อ

repo นี้ตั้งใจทำให้ง่ายที่สุด ปัญหาด้านล่างทั้งหมดเห็นได้จริงในกราฟตัวอย่าง ([examples/thai-tourism/graph.json](../examples/thai-tourism/graph.json)) ลองเปิดดูประกอบ

## 1. Entity resolution — สิ่งเดียวกัน แต่กลายเป็นหลาย node

`key()` รวม node ได้เฉพาะชื่อที่สะกดเหมือนกันทุกตัวอักษร (ต่างกันได้แค่ตัวพิมพ์เล็ก/ใหญ่และช่องว่าง) แต่ข้อความภาษาไทยเรียกสิ่งเดียวกันได้หลายแบบ:

| node ที่แยกกัน | ที่จริงคือ |
|---|---|
| `สงกรานต์`, `ประเพณีสงกรานต์` | สิ่งเดียวกัน |
| `ภาคอีสาน`, `ภาคตะวันออกเฉียงเหนือ` | สิ่งเดียวกัน (LLM เชื่อมไว้ด้วย edge `ALSO_KNOWN_AS` แต่ node ยังไม่รวมกัน) |

**ผลเสีย:** ข้อเท็จจริงกระจายไปหลาย node

```
(ถนนข้าวสาร) ─USED_FOR─▶ (สงกรานต์)                ← เกาะที่ 1
(ยูเนสโก) ─REGISTERED_...─▶ (ประเพณีสงกรานต์) ─REGISTERED_IN─▶ (พ.ศ. 2566)   ← เกาะที่ 2
```

ถ้าถามว่า *"ประเพณีที่เล่นกันที่ถนนข้าวสาร ได้รับการขึ้นทะเบียนจากยูเนสโกในปีใด"* ตอนทดสอบระบบตอบถูก (พ.ศ. 2566) แต่ดูเส้นทางที่มันอธิบาย:

```
(ถนนข้าวสาร) → (สงกรานต์) → [เป็นสิ่งเดียวกับ] → (ประเพณีสงกรานต์) → (พ.ศ. 2566)
```

edge `เป็นสิ่งเดียวกับ` **ไม่มีอยู่ในกราฟ** LLM เชื่อมเองเพราะชื่อคล้ายกัน ครั้งนี้เดาถูก แต่เป็นการเดาที่ตรวจสอบไม่ได้ ซึ่งเป็นสิ่งที่ GraphRAG ตั้งใจจะหลีกเลี่ยง

**วิธีแก้ (เรียงจากง่ายไปยาก):**
- รวม node ที่ LLM บอกว่าเป็น `ALSO_KNOWN_AS` / `SAME_AS` เข้าด้วยกัน
- ตารางชื่อเรียกอื่น (alias) ที่เขียนเอง เช่น `อีสาน = ตะวันออกเฉียงเหนือ`
- ตัดคำนำหน้าทั่วไปก่อนทำ key เช่น `ประเพณี`, `จังหวัด`, `งาน`
- เทียบ embedding ของชื่อ node แล้วให้ LLM ยืนยันคู่ที่คล้ายกัน
- ส่งรายชื่อ entity ที่มีอยู่แล้วไปใน prompt ตอน extract เพื่อให้ LLM ใช้ชื่อเดิมซ้ำ

## 2. Relation ไม่มี schema — ชื่อ relation ไม่สม่ำเสมอ

การขึ้นทะเบียนของยูเนสโกอย่างเดียว ในกราฟเดียวกันได้ relation ออกมาถึง 3 ชื่อ:

```
(ยูเนสโก) -[REGISTERED]-> (อุทยานประวัติศาสตร์สุโขทัย)
(ยูเนสโก) -[REGISTERED_AS_WORLD_HERITAGE]-> (กลุ่มป่าดงพญาเย็น-เขาใหญ่)
(ยูเนสโก) -[REGISTERED_INTANGIBLE_CULTURAL_HERITAGE]-> (โขน)
```

ปีที่ขึ้นทะเบียนก็มีทั้ง `REGISTERED_DATE` และ `REGISTERED_IN` นอกจากนี้ยังมี relation กว้างๆ อย่าง `IS` เช่น `(ดอยอินทนนท์) -[IS]-> (ยอดเขาที่สูงที่สุดในประเทศไทย)` ซึ่งทำให้ประโยคบรรยายทั้งประโยคกลายเป็น node

ผลคือถ้าเขียน query ว่า "หามรดกโลกทั้งหมด" ด้วย relation เดียว จะได้ผลไม่ครบ

**วิธีแก้:** กำหนด **ontology** ใน prompt ให้ใช้ได้เฉพาะ relation ในรายการ เช่น

```
LOCATED_IN, PART_OF, HELD_IN, ORIGINATED_IN, FILMED_AT,
WORLD_HERITAGE_OF, INTANGIBLE_HERITAGE_OF, FAMOUS_FOR
```

แล้วกรอง triple ที่ไม่อยู่ในรายการทิ้ง กราฟจะสะอาดขึ้นมาก ส่วนคุณสมบัติอย่าง "สูงที่สุดในประเทศ" ควรเก็บเป็น attribute ของ node แทน

## 3. วันที่และตัวเลขเป็น node

`พ.ศ. 2534` เป็น node ประเภท `Date` ซึ่งเชื่อมกับทั้ง `อุทยานประวัติศาสตร์สุโขทัย` และ `เขตรักษาพันธุ์สัตว์ป่าทุ่งใหญ่นเรศวร-ห้วยขาแข้ง` ทำให้สองที่นี้ห่างกันแค่ 2 hops ในกราฟ ทั้งที่ไม่ได้เกี่ยวข้องกันเลย แค่บังเอิญขึ้นทะเบียนปีเดียวกัน ผลคือ k-hop ดึง facts ที่ไม่เกี่ยวข้องมาด้วย

**วิธีแก้:** เก็บปีเป็น *attribute* ของ edge หรือ node เช่น `registered_year=2534` แทนการสร้างเป็น node

## 4. ข้อมูลหายตอน extract

สิ่งที่ไม่ได้ถูกดึงเป็น triple ถือว่าไม่มีอยู่ในกราฟ ตอนทดลองรอบแรก ประโยค "อ่าวมาหยาบนเกาะพีพีเล" ไม่ได้บอกว่าเกาะพีพีเลเป็นส่วนหนึ่งของหมู่เกาะพีพี กราฟจึงขาดช่วง และตอบไม่ได้ว่า The Beach ถ่ายทำที่จังหวัดไหน ทั้งที่คนอ่านรู้ได้ทันที ต้องแก้ข้อความให้บอกตรงๆ ก่อน LLM จึงจะดึงออกมา นอกจากนี้ LLM ไม่ deterministic ทำให้ ingest แต่ละรอบได้ triples ไม่เหมือนกัน

**วิธีแก้:** ทำแบบ hybrid ([บทที่ 3](03-graphrag-vs-rag.md)) คือแนบ chunk ต้นฉบับผ่าน `source_chunk` ไปพร้อมกับ facts หรือเสริมกราฟด้วยข้อมูลที่มีโครงสร้างอยู่แล้ว (เช่น ตารางจังหวัด → ภาค)

## 5. ข้อจำกัดด้านขนาด

- `find_seeds()` ส่ง **ชื่อ node ทั้งหมด** ไปให้ LLM ซึ่งใช้ได้กับกราฟหลักสิบหรือหลักร้อย node แต่ถ้าเป็นหลักหมื่น (เช่น สถานที่ท่องเที่ยวทั้งประเทศ) จะเกิน context ควรเปลี่ยนไปใช้ vector index หรือ full-text search บนชื่อ node แทน
- NetworkX เก็บทุกอย่างไว้ใน memory เหมาะกับการทดลอง ถ้าต้องใช้จริงให้ย้ายไป graph database อย่าง **Neo4j** แล้วเขียน `MERGE` ด้วย Cypher จะได้ query แบบ `shortestPath`, index และ transaction

## 6. ขั้นถัดไป: คำถามระดับภาพรวม

คำถามอย่าง "ถ้าชอบธรรมชาติควรไปเที่ยวภาคไหน" ไม่มี seed entity ให้เริ่ม แนวทางของ Microsoft GraphRAG คือ

1. แบ่งกราฟเป็นกลุ่มด้วย `nx.community.louvain_communities` (เช่น อาจได้กลุ่ม "ทะเลภาคใต้" "มรดกโลก" "ประเพณีอีสาน")
2. ให้ LLM สรุปแต่ละกลุ่ม
3. ตอบคำถามจากบทสรุปของกลุ่มเหล่านั้น
