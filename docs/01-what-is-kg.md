# 1. Knowledge Graph คืออะไร

Knowledge Graph คือการเก็บความรู้ในรูปของ **สิ่งต่างๆ (entity)** และ **ความสัมพันธ์ (relation)** ระหว่างสิ่งเหล่านั้น แทนการเก็บเป็นย่อหน้าข้อความ

ข้อความ:

> หมู่เกาะพีพีอยู่ในจังหวัดกระบี่

เมื่อเก็บเป็นกราฟจะได้:

```
(หมู่เกาะพีพี) ──LOCATED_IN──▶ (จังหวัดกระบี่)
```

## ส่วนประกอบหลัก

| คำศัพท์ | ความหมาย | ตัวอย่างจากกราฟของเรา |
|---|---|---|
| **Node / Entity** | "สิ่ง" หนึ่งอย่าง เช่น สถานที่ องค์กร เทศกาล ปี | `ดอยอินทนนท์`, `ยูเนสโก`, `พ.ศ. 2534` |
| **Type** | ประเภทของ node | `Place`, `Organization`, `Event`, `Date` |
| **Edge / Relation** | ความสัมพันธ์แบบมีทิศทางระหว่างสอง node | `LOCATED_IN`, `HELD_AT`, `FILMED_AT` |
| **Triple** | หน่วยข้อเท็จจริงที่เล็กที่สุด คือ `(subject, relation, object)` | `(ฟูลมูนปาร์ตี้, HELD_AT, เกาะพะงัน)` |
| **Ontology / Schema** | ข้อกำหนดว่าอนุญาตให้มี type และ relation อะไรบ้าง | repo นี้ยังไม่ได้กำหนดตายตัว (ดู[บทที่ 4](04-limitations.md)) |

**ทิศทางของ edge มีความหมาย** เช่น `(เกาะสมุย) -LOCATED_IN-> (จังหวัดสุราษฎร์ธานี)` อ่านว่า "เกาะสมุยอยู่ในจังหวัดสุราษฎร์ธานี" ถ้ากลับทิศ ความหมายจะผิด

## ทำไมต้องเป็นกราฟ

ลองดูข้อเท็จจริงสองข้อที่อยู่ **คนละย่อหน้า** ใน sample.txt:

1. "ประเพณียี่เป็งของเชียงใหม่ตรงกับประเพณีลอยกระทง" (ย่อหน้าที่ 2)
2. "เชื่อกันว่าประเพณีลอยกระทงมีต้นกำเนิดที่สุโขทัย" (ย่อหน้าที่ 2)
3. "เชียงใหม่จัดประเพณียี่เป็ง" (ย่อหน้าที่ 1)

ในข้อความ ประโยคเหล่านี้กระจายกันอยู่ แต่ในกราฟทั้งหมดเชื่อมกันผ่าน node ที่ใช้ร่วมกัน:

```
(จังหวัดเชียงใหม่) ◀─HELD_IN─ (ประเพณียี่เป็ง) ─EQUIVALENT_TO─▶ (ประเพณีลอยกระทง) ─ORIGINATED_IN─▶ (จังหวัดสุโขทัย)
```

คำถามอย่าง "ประเพณีที่ตรงกับยี่เป็งมีต้นกำเนิดที่จังหวัดใด" จึงตอบได้ด้วยการ **เดินตาม edge** สองก้าว ซึ่งเรียกว่า *2-hop* เราไม่ต้องหวังว่าจะมีประโยคไหนเขียนคำตอบนี้ไว้ตรงๆ

ตัวอย่างที่ยาวกว่านี้คือ ภาพยนตร์ The Beach กับจังหวัดที่ใช้ถ่ายทำ ต้องเดินถึง 4 ก้าว:

```
(The Beach) ─FILMED_AT─▶ (อ่าวมาหยา) ─LOCATED_IN─▶ (เกาะพีพีเล) ─PART_OF─▶ (หมู่เกาะพีพี) ─LOCATED_IN─▶ (จังหวัดกระบี่)
```

สรุปสิ่งที่กราฟให้ได้:

- **รวมข้อมูลจากหลายที่** — entity เดียวกันที่ถูกพูดถึงในหลายเอกสาร จะกลายเป็น node เดียวกัน
- **ตอบคำถามเชิงความสัมพันธ์** — "อะไรอยู่ที่ไหน เกี่ยวข้องกับอะไร ผ่านอะไร"
- **อธิบายที่มาได้** — คำตอบชี้กลับไปที่ triple ที่ใช้ได้เสมอ
- **มองภาพรวมได้** — เช่น "มรดกโลกทั้งหมดในภาคอีสาน" หรือ "ภาคใต้มีจังหวัดท่องเที่ยวอะไรบ้าง" ทำได้ด้วยการนับหรือรวม edge

## ดูกราฟจริง

```bash
uv run main.py stats
```

```
    9  ยูเนสโก (Organization)
    5  จังหวัดเชียงใหม่ (Place)
    5  ภาคอีสาน (Place)
    4  อุทยานประวัติศาสตร์สุโขทัย (Place)
    ...
```

ตัวเลขด้านหน้าคือ **degree** หรือจำนวน edge ที่เชื่อมกับ node นั้น node ที่มี degree สูงคือ "ศูนย์กลาง" ของเรื่อง ในตัวอย่างนี้ `ยูเนสโก` เป็นศูนย์กลาง เพราะเชื่อมกับมรดกโลกและมรดกทางวัฒนธรรมทุกแห่ง ส่วน `uv run main.py viz` จะสร้าง [examples/thai-tourism/graph.html](../examples/thai-tourism/graph.html) ให้ลากดูกราฟได้
